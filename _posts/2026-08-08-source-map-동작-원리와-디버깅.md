## 표면적 이해
Source Map은 개발자 도구에서 실제 소스코드를 확인할 수 있게 해주는 중요한 도구입니다.

## Deep Dive

### 왜 필요한가?
- Source Map은 빌드 과정에서 소스코드가 압축되어 변경됨으로 인해 발생하는 디버깅의 어려움을 해결합니다.
- 이전 방식에서는 개발자 도구에서 실제 소스코드를 확인할 수 없어 디버깅이 힘들었습니다.

### 내부 동작 원리
- Source Map은 소스코드와 변환된 코드의 Mapping 정보를 저장합니다.
- 개발자 도구는 이 Mapping 정보를 사용하여 실제 소스코드를 표시합니다.
```
+---------------+
|  원본 소스   |
+---------------+
       |
       |
       v
+---------------+
|  변환된 코드  |
+---------------+
       |
       |
       v
+---------------+
|  Source Map   |
+---------------+
       |
       |
       v
+---------------+
| 개발자 도구  |
+---------------+
```

### 코드로 이해하기

```typescript
// 예시: webpack.config.js
module.exports = {
  devtool: 'inline-source-map',
  // ...
}
```

```typescript
// 잘못된 사용 예: Source Map을 사용하지 않았을 때
function add(a, b) {
  return a + b;
}

// 올바른 사용 예: Source Map을 사용했을 때
function add(a, b) {
  // Source Map이 포함된 코드
  return a + b;
}
```

### 비교 분석

| 구분 | 개발자 도구에서 소스코드 표시 | 디버깅 어려움 |
|------|----------------------------|---------------|
| Source Map 사용 | 가능 | 낮음           |
| Source Map 미사용 | 불가능 | 높음           |
| 기존 방식    | 불가능 | 매우 높음      |

### 실전 팁
- Best Practice: Source Map을 항상 사용하여 디버깅을 쉽게 만들어야 합니다.
- 흔한 실수: Source Map을 사용하지 않거나, 잘못된 설정으로 인해 디버깅이 어려워질 수 있습니다.
- 성능 관련 주의사항: Source Map을 생성하는 과정에서 빌드 시간이 증가할 수 있습니다.

### 한 줄 정리
Source Map은 개발자 도구에서 실제 소스코드를 확인할 수 있게 해주는 중요한 도구로서, 디버깅을 쉽게 만들어 줍니다.
