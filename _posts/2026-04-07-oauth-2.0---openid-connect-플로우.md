## 표면적 이해
OAuth 2.0와 OpenID Connect는 인증과 승인을 처리하는 프로토콜로 사용자에게 편리하고 한 사용자 경험을 제공한다.

## Deep Dive

### 왜 필요한가?
이전에는 사용자가 각 서비스에 로그인할 때마다 아이디와 비밀번호를 입력해야 했지만, OAuth 2.0와 OpenID Connect를 사용하면 하나의 아이디와 비밀번호로 여러 서비스에 액세스할 수 있다. 또한, 이전 방식의 한계였던 아이디와 비밀번호를 여러 서비스에 노출하는 위험을 줄일 수 있다.

### 내부 동작 원리
_core_ OAuth 2.0와 OpenID Connect의 핵심 메커니즘은 다음과 같다. 
- 클라이언트(예: 웹 애플리케이션)가 사용자에게 인증을 요청하면, 사용자는 인증 서버(예: Google, Facebook)로 리렉트된다.
- 사용자가 인증 서버에서 로그인하면, 인증 서버는 클라이언트에게 인증 코드를 발급한다.
- 클라이언트는 인증 코드를 사용하여 인증 서버에서 액세스 토큰을 발급받는다.
- 클라이언트는 액세스 토큰을 사용하여 보호된 리소스에 액세스할 수 있다.
 
다음은 ASCII 다이어그램으로 나타낸 OAuth 2.0의 내부 동작 원리이다.
```
  +--------+                                   +---------------+
  |        |                                   |               |
  |  클라이언트  |                                   |  인증 서버  |
  |        |                                   |               |
  +--------+                                   +---------------+
           |                                            |
           |  인증 요청                                  |  인증 코드 발급
           |  ---------------------------->              |  <-------------------
           |                                            |
           |  인증 코드                                  |  액세스 토큰 발급
           |  <-------------------                      |  <-------------------
           |                                            |
           |  액세스 토큰                                 |  리소스 제공
           |  --------------------->                    |  <-------------------
           |                                            |
```

### 코드로 이해하기
다음은 TypeScript로 작성된 OAuth 2.0 클라이언트의 예제 코드이다.
```typescript
import axios from 'axios';

// 인증 서버의 클라이언트 아이디와 시크릿 키
const clientId = 'your_client_id';
const clientSecret = 'your_client_secret';

// 인증 서버의 로그인 URL
const loginUrl = 'https://example.com/login';

// 인증 서버의 토큰 발급 URL
const tokenUrl = 'https://example.com/token';

// 사용자로부터 로그인 요청을 받았을 때,
// 사용자를 인증 서버의 로그인 페이지로 리렉트한다.
function login() {
  const authUrl = `${loginUrl}?client_id=${clientId}&redirect_uri=${redirectUri}`;
  window.location.href = authUrl;
}

// 사용자가 인증_SERVER에서 로그인하면,
// 인증 서버는 사용자를 리다이렉트 URI로 리다이렉트한다.
// 이 때, 인증 코드를 쿼리 파라미터로 전달한다.
function getToken(authCode: string) {
  const tokenUrlWithParams = `${tokenUrl}?code=${authCode}&client_id=${clientId}&client_secret=${clientSecret}&redirect_uri=${redirectUri}`;
  axios.post(tokenUrlWithParams)
    .then((response) => {
      const accessToken = response.data.access_token;
      // 액세스 토큰을 사용하여 보호된 리소스에 액세스한다.
      useAccessToken(accessToken);
    })
    .catch((error) => {
      console.error(error);
    });
}

// 액세스 토큰을 사용하여 보호된 리소스에 액세스한다.
function useAccessToken(accessToken: string) {
  const resourceUrl = 'https://example.com/resource';
  axios.get(resourceUrl, {
    headers: {
      Authorization: `Bearer ${accessToken}`,
    },
  })
    .then((response) => {
      console.log(response.data);
    })
    .catch((error) => {
      console.error(error);
    });
}
```

### 비교 분석
| 인증 프로토콜 | OAuth 2.0 | OpenID Connect |
| --- | --- | --- |
| 목적 | 리소스 액세스 | 인증 및 리소스 액세스 |
| 인증 코드 | 지원 | 지원 |
| 액세스 토큰 | 지원 | 지원 |
| ID 토큰 | 지원하지 않음 | 지원 |
| 사용자 정보 | 제공하지 않음 | 제공 |

### 실전 팁
- 클라이언트 아이디와 시크릿 키를 안전하게 보관한다.
- 리디렉트 URI를 안전하게 등록한다.
- 액세스 토큰의 유효성을 확인한다.
- ID 토큰의 유효성을 확인한다.

### 한 줄 정리
OAuth 2.0와 OpenID Connect는 인증과 승인을 처리하는 프로토콜로 사용자에게 편리하고 안전한 사용자 경험을 제공한다.
