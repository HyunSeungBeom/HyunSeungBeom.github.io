## 표면적 이해
Next.js 캐싱 전략은 요청 메모화, 데이터 캐시, 전체 루트 캐시를 통해 성능을 향상시키는 방법이다.

## Deep Dive

### 왜 필요한가?
- 캐싱 전략은 서버 부하를 줄이고, 클라이언트 응답 시간을 단축하는 데 필요한 기술입니다.
- 이전 방식의 한계는 서버에 매번 요청을 보내어 데이터를 가져와야 한다는 점입니다. 매번 동일한 데이터를 가져오기 때문에 불필요한 요청이 발생하게 됩니다.

### 내부 동작 원리
- Next.js 캐싱 전략은 Request Memoization, Data Cache, Full Route Cache를 통해 작동합니다.
- Request Memoization은 이전에 요청한 데이터를 캐싱하여 동일한 요청이 들어왔을 때 캐싱된 데이터를 반환합니다.
- Data Cache는 데이터를 캐싱하여 데이터베이스나 서버에 요청하지 않도록 합니다.
- Full Route Cache는 전체 페이지를 캐싱하여 페이지가 다시 렌더링되지 않도록 합니다.
```
                          +---------------+
                          |  클라이언트   |
                          +---------------+
                                    |
                                    |  요청
                                    v
                          +---------------+
                          |  Next.js     |
                          |  (Request    |
                          |   Memoization) |
                          +---------------+
                                    |
                                    |  캐싱된 데이터
                                    v
                          +---------------+
                          |  캐싱      |
                          |  (Data Cache)  |
                          +---------------+
                                    |
                                    |  캐싱된 데이터
                                    v
                          +---------------+
                          |  데이터베이스 |
                          |  (Server)      |
                          +---------------+
```

### 코드로 이해하기

```typescript
// next.config.js
module.exports = {
  //...
  experimental: {
    cache: {
      maxAge: 60, // 1분
    },
  },
}
```

```typescript
// pages/_app.tsx
import { useState, useEffect } from 'react';

function App() {
  const [data, setData] = useState([]);

  useEffect(() => {
    fetch('/api/data')
      .then(response => response.json())
      .then(data => setData(data));
  }, []);

  return (
    <div>
      {data.map(item => (
        <div key={item.id}>{item.name}</div>
      ))}
    </div>
  );
}

export default App;
```

```typescript
// pages/api/data.ts
import { NextApiRequest, NextApiResponse } from 'next';

const data = [
  { id: 1, name: 'John' },
  { id: 2, name: 'Jane' },
];

export default async function handler(
  req: NextApiRequest,
  res: NextApiResponse
) {
  return res.status(200).json(data);
}
```

### 비교 분석

| 구분 | Request Memoization | Data Cache | Full Route Cache |
|------|-------------------|-----------|------------------|
| 캐싱 대상 | 요청 | 데이터 | 전체 페이지 |
| 캐싱 기간 | 1분 | 1시간 | 1일 |
| 요청 수 | 줄어듬 | 줄어듬 | 없음 |

### 실전 팁
- 캐싱 기간을 너무 길게 설정하면 데이터가 최신이 아닐 수 있으므로 주의합니다.
- 캐싱을 사용하면 데이터베이스나 서버에 요청이 줄어들어 서버 부하가 줄어듭니다.
- 캐싱은 클라이언트 측에서뿐만 아니라 서버 측에서도 사용할 수 있습니다.

### 한 줄 정리
Next.js 캐싱 전략은 캐싱 기간과 캐싱 대상에 따라 성능을 향상시키는 데 중요한 역할을 합니다.
