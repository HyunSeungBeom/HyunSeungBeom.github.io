## 표면적 이해
콘텐츠 보안 정책(CSP) 설정과 활용은 웹 애플리케이션의 보안을 강화하기 위한 중요한 기술입니다.

## Deep Dive

### 왜 필요한가?
콘텐츠 보안 정책(CSP) 설정과 활용이 필요한 이유는 웹 애플리케이션의 보안을 강화하기 위해서입니다. 이전 방식에서는 XSS(크로스 사이트 스크립팅) 공격이 쉽게 발생할 수 있었으며, 이를 방지하기 위한 방법이 필요했습니다. CSP는 웹 애플리케이션의 보안을 강화하기 위한 중요한 기술입니다.

### 내부 동작 원리
CSP의 내부 동작 원리는 다음과 같습니다. CSP는 웹 브라우저와 서버가 komunikuje하는 프로세스입니다. 브라우저는 서버에서 받은 HTML 문서와 함께 CSP를 같이 받습니다. 브라우저는 받은 CSP에 따라 웹 애플리케이션의 보안을 설정합니다.
```
  +---------------+
  |  브라우저   |
  +---------------+
           |
           |
           v
  +---------------+
  |  서버(CSP)  |
  +---------------+
           |
           |
           v
  +---------------+
  |  HTML 문서   |
  +---------------+
```
이 다이어그램은 브라우저와 서버가 komunikuje하는 프로세스를 보여줍니다. 브라우저는 서버에서 받은 HTML 문서와 함께 CSP를 같이 받습니다. 브라우저는 받은 CSP에 따라 웹 애플리케이션의 보안을 설정합니다.

### 코드로 이해하기
다음은 실제 동작을 보여주는 코드 예제입니다.
```typescript
// CSP 설정
const csp = "default-src 'self'; script-src 'self' https://example.com;";

// HTML 문서에 CSP 설정
const html = `
  <html>
    <head>
      <meta http-equiv="Content-Security-Policy" content="${csp}">
    </head>
    <body>
      <script src="https://example.com/script.js"></script>
    </body>
  </html>
`;
```
이 예제는 CSP를 설정하고, HTML 문서에 CSP를 설정하는 방법을 보여줍니다.

```typescript
// 잘못된 사용 예
const csp = "default-src *;";

// 올바른 사용 예
const csp = "default-src 'self'; script-src 'self' https://example.com;";
```
이 예제는 잘못된 사용 예와 올바른 사용 예를 보여줍니다. 잘못된 사용 예는 모든 출처에서 스크립트를 실행하도록 설정합니다. 올바른 사용 예는 자신의 도메인과 특정 도메인에서 스크립트를 실행하도록 설정합니다.

### 비교 분석
다음은 CSP 설정의 비교 분석표입니다.

| 구분 | Default | Self | None |
|------|---------|------|------|
| 모든 출처 허용 | O | X | X |
| 자신의 도메인 허용 | X | O | X |
| 스크립트 허용 | X | O | X |

### 실전 팁
CSP 설정과 활용에 대한 실전 팁은 다음과 같습니다.
- Best Practice: CSP를 설정할 때, 자신의 도메인과 특정 도메인에서 스크립트를 실행하도록 설정해야 합니다.
- 흔한 실수: 모든 출처에서 스크립트를 실행하도록 설정하는 것입니다.
- 성능 관련 주의사항: CSP 설정이 성능에 영향을 줄 수 있습니다. 따라서, CSP 설정을 최적화해야 합니다.
