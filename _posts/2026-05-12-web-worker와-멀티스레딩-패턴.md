## 표면적 이해
웹 브라우저에서 단일 스레드인 메인 스레드의 작업량을 분산시키기 위해 사용되는 기술을 소개한다.

## Deep Dive

### 왜 필요한가?
- 웹 브라우저에서 자바스크립트 코드가 실행되는 메인 스레드는 단일 스레드이므로, CPU 집중적인 작업을 수행하면 페이지의 반응성을 손상시킨다.
- 이전 방식에서는 Timer 함수나 다른 방식을 사용했지만, 이러한 방식은 제한적이고 예측하기 어렵다.

### 내부 동작 원리
- 웹 브라우저에서 웹 워커를 생성하면, 새로운 스레드가 생성되어 별도의 환경에서 작업을 수행한다.
- 웹 워커는 메인 스레드와적인 실행 환경을 가지므로, 메인 스레드의 작업에 영향을 주지 않는다.
 
```
+---------------+
|  웹 브라우저  |
+---------------+
          |
          |
          v
+---------------+
|  메인 스레드  |
+---------------+
          |
          |
          v
+---------------+
|  웹 워커 생성  |
+---------------+
          |
          |
          v
+---------------+
|  웹 워커 스레드  |
+---------------+
```

### 코드로 이해하기

```typescript
// 메인 스레드에서 웹 워커 생성
const worker = new Worker('worker.js');

// 웹 워커에서 메인 스레드로 메시지 전송
worker.postMessage('메시지 전송');

// 웹 워커에서 수행할 작업
worker.onmessage = (event) => {
    console.log(event.data);
}
```

```typescript
// worker.js
// 메인 스레드에서 전송한 메시지 수신
self.onmessage = (event) => {
    console.log(event.data);
    // CPU 집중적인 작업 수행
    const result = performCpuIntensiveTask();
    // 메인 스레드로 결과 전송
    self.postMessage(result);
}
```

### 비교 분석

| 구분 | 싱글 스레드 | 멀티 스레드 | 웹 워커 |
|------|------------|------------|---------|
| CPU 사용 | 메인 스레드만 사용 | 여러 스레드 사용 | 별도 스레드 사용 |
| 메모리 사용 | 메인 스레드와 공유 | 별도 메모리 공간 | 별도 메모리 공간 |
| 자바스크립트 환경 | 메인 스레드와 동일 | 별도 환경 | 별도 환경 |

### 실전 팁
- 웹 워커를 생성할 때, 같은 도메인에서 생성해야 하며, 동일한 도메인이 아닌 경우 크로스 오리진 리소스 공유 CORS 정책에 의해 제한된다.
- 웹 워커에서 DOM 조작이 불가능하며, 메인 스레드와의 통신을 위해.postMessage() 메소드를 사용한다.
- 웹 워커는 웹 브라우저에서만 사용할 수 있으므로, Node.js 환경에서는 사용할 수 없다.
